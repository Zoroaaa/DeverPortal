## 是什么

一个单机像素风回合制 RPG。玩家从青溪山门出发，沿灵脉遗迹走过十九境，探索、采集、结契、解碑，最后在归墟面对「新契」或「断契」两种结局。

前端是 Phaser 3.90 加原生 JavaScript，脚本按 `index.html` 的顺序加载，没有打包步骤。游戏数据放在 `public/js/data/`：五行与状态、技能与灵诀、62 种灵兽、材料道具配方、灵器、Boss、十九境地图、任务、剧情抉择、山海志。`world / battle / ui / main` 四层消费这些数据，通过 `window.LB` 暴露主控接口。后端是一个 Cloudflare Worker（`src/index.js`）加 D1，只管账号和云存档，静态资源和 `/api/*` 同源。

> 证据：README「核心玩法」「技术栈」「目录结构」；`public/js/` 的分层；`src/index.js`。

## 为什么做

它要解决的问题写在玩法里：单机、无构建、离线可玩，存档优先落在本地，云存档只是可选的备份层。第一条 commit 就是「初始化灵兽录：Phaser 3 前端与 Cloudflare Worker 云存档」，之后内容按地图、灵兽、Boss、灵器一层层铺开。

> 证据：README「世界观」「技术栈」「存档与云同步」；git log 首条 `6ac5d1f`；`public/js/main/main-state.js` 的 `SAVE_KEY`。

## 能力边界

**做了的：**

- 探索：19 张地图、点击寻路、WASD / 方向键、移动端摇杆、小地图；天时和天气会改五行威力和稀有灵兽出现率。
- 战斗：回合制按速度排序，3 只队伍可中途换人；五行相克、6 种状态、契势满 100 发动合契；13 场 Boss、4 种 AI 原型、Boss 不可结契；自动战斗和 1x / 2x / 跳过。
- 养成：62 种灵兽、等级上限 40、4 个随等级解锁的技能、12 种灵诀、28 件灵器与 6 套套装、灵兽栏可升到 5 级。
- 剧情：12 章主线、63 条支线、3 类悬赏、12 处抉择影响立场与声望、90 条山海志、78 处碑文、8 层山海试炼、两种结局。
- 经济与制作：5 家商店、14 种材料、16 种道具、16 张配方。
- 存档：本地 localStorage 优先，登录后每 2 秒防抖推云；冲突时给「本机 / 云端」双版本对比。
- 离线与可访问性：PWA 缓存、键盘操作、`role="dialog"` 与焦点恢复、大字号、减少动效。

**明确没做的：**

- 云端只有一份存档，`saves` 表以 `user_id` 为主键，没有多槽位或版本历史。
- 账号只有道号加密语；README 的 API 表里没有邮箱、找回密码、改密。
- API 表里没有联机、排行、好友这类接口，战斗和探索都按单机写。
- 未登录或接口异常时不碰云端，只落本地。

## 实现要点

- 无构建：`index.html` 的加载顺序就是依赖顺序，所有模块通过全局命名空间协作，新增文件要同步登记。代价是依赖顺序靠人维护，README 把这条写在目录结构后面。
- 数据与渲染分开：`js/data` 只给纯数据，`world / battle / ui / main` 各自消费。启动时跑 `validateContent()`，检查坐标、可达性和区域 / Boss / 灵兽 / 技能 / 配方之间的引用；内容写错先在自检里报。
- 灵兽立绘是程序化 SVG：每只 64×64 逻辑网格上由 `PixelCanvas` 画 rect，不引入图片和依赖；同一份 `draw` 同时出图鉴小图和详情大图；`art-check` 卡总 rect ≤ 60000、单兽 ≤ 900，同家族不能换色复制。`docs/beast-art.md` 开头记录过试做「解剖 + 材质」新引擎、可读性不如旧版后整体移除。
- 存档冲突只认明显更新的版本：客户端 2 秒防抖，服务端超过 2 秒才算冲突，并把客户端 `updatedAt` 钳到服务器当前时间，避免未来时间锁死账号。
- 认证是 PBKDF2-SHA256 10 万次迭代加 16 字节随机盐，会话 30 天。
- Worker 一个文件：`/api/*` 自己处理，其余交给 `ASSETS` 绑定；限流是单 isolate 的 `Map`，12 次 / 分钟 / IP。
- UI 的设计 token 集中在 `public/style.css` 顶部，规范写在 `docs/ui-guidelines.md`；`ui:check` 查对比度、ARIA、重复 id 和脚本语法。

> 证据：README「目录结构」「内容校验」「存档与云同步」「API」；`docs/beast-art.md` 文首说明与 §1–2；`docs/ui-guidelines.md`；`public/cloud.js`；`src/index.js`。

## 怎么用

门槛：

- 需要 Node 和 Wrangler 4；仓库的 devDependencies 只有 `wrangler ^4`，package.json 没有声明 Node 版本。
- 云存档要 D1。只想跑前端可以跳过，但云存档不可用，本地存档正常。
- 部署前把 `wrangler.jsonc` 的 `database_id` 换成自己的，现在填的是作者的生产库 ID。
- 没有构建步骤；改完 `public/` 下的资源跑 `npm run version:bump`，不要手改 `?v=`。

```bash
git clone https://github.com/Zoroaaa/lingbeast.git
cd lingbeast
npm install
npm run db:init:local    # 初始化本地 D1
npm run dev              # http://localhost:8787
```

部署：

```bash
npx wrangler d1 create lingbeast   # 返回的 ID 填进 wrangler.jsonc
npm run db:init:remote
npm run deploy
```

只想玩的话，直接开 https://lingbeast.wort.uk/ 。
