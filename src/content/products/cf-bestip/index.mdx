## 是什么

cf-bestip 是一个 Python 扫描脚本，产出两类东西：Cloudflare 优选 IP，和能用的公开代理。

一次运行的顺序是：先跑内部自检（CF IP 段、数据源、检测 API、代理抽样），再从四个源收集代理，逐个用检测 API 验延迟、HTTPS 支持和地理位置，然后随机采样 Cloudflare IP 段做并发测速，最后按地区排序输出。

结果落在 `public/`：`ip_all.txt`、`ip_<地区>.txt`、`proxy_all.txt`、`proxy_<地区>.txt`、`ip_candidates.json`，外加一个 `index.html` 可视化页面。README 的 GitHub Actions 每天自动跑一轮，把这些文件发布到 GitHub Pages，现成结果在 https://zoroaaa.github.io/cf-bestip/ 。

> 证据：`README.md`「项目简介」「核心特性」「系统架构」流程图「快速开始 › 输出位置」「📄 输出文件」；快照 `src/data/github/cf-bestip.json`（homepage、license）。

## 实现要点

- 纯 Python，运行时只依赖 `requirements.txt` 里的包和 `curl`；`ip.py` 是主流程，`proxy_sources.py` 负责抓源，`tests` 里放内部测试和代理验证，`config.py` 集中所有参数。
- 并发用 `ThreadPoolExecutor`，默认 24 线程；每个环节都有独立超时（扫描 15s、代理测试 10s），多层超时防止挂起。
- 四个源的格式各不相同（JSON、DataTables API、TXT、HTML 表格），所以解析按源分开写，HTML 那条用 BeautifulSoup。
- 结果不是「有就输出」：每个节点有分数，按地区取前 6，低于延迟上限才进入列表。
- 部署侧不依赖服务器：Actions 定时跑完直接提交到 Pages，相当于把「定时任务 + 静态托管」都交给了 GitHub。

> 证据：`README.md`「系统架构」「配置说明 › 核心配置 / 地区映射」「数据源」「性能优化/线程池」段；`config.py` 的 `MAX_WORKERS`、`TIMEOUT`、`PROXY_TEST_TIMEOUT`、`MAX_OUTPUT_PER_REGION`；`README.md`「自动化部署」。

## 怎么用

前置：Python 3.11+、curl、Git。

```bash
git clone https://github.com/Zoroaaa/cf-bestip.git
cd cf-bestip
pip install -r requirements.txt

# 先自检：IP 段、数据源、检测 API 能不能通
python -c "from tests import run_internal_tests; run_internal_tests()"

# 开始扫描
python ip.py
```

结果看 `public/`。要调参数就改 `config.py`：采样量（`SAMPLE_SIZE_PER_REGION` / `TOTAL_SAMPLE`）、并发（`MAX_WORKERS`）、延迟上限（`LATENCY_LIMIT`）、每地区输出数（`MAX_OUTPUT_PER_REGION`），以及必须换掉的 `PROXY_CHECK_API_URL` / `PROXY_CHECK_API_TOKEN`。

README 的克隆命令里是 `yourusername` 占位，换成上面的仓库地址。只想拿现成结果的话，直接开 Pages 页面，不用本地跑。
